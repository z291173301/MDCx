> 组内站点按「该类型专属站 → 有码+素人 → 综合站」排列，前面的站优先级更高。
> **「国产短剧」组 2.6.0 起只挂 `JavDay` 一个站**（原「素人番号」组 28 站全部移除，配置字段名仍是 `website_suren`）：国产短剧条目**本身没有番号**，JavDay 只给站内随机 ID（`/videos/Gb5WuoJw/`），文件名也是千奇百怪没有统一格式，既**不能按路径或文件名自动识别**，别的站又全靠番号查——查不到就是查不到，留在组里只会给每条影片白挂一次请求。故这一组只在**「锁定刮削类型」选「国产短剧」**时才生效（走 JavDay 的站内搜索页按剧名找页面，或用户手动指定页面），程序不做任何 DUANJU 自动识别；**以前的素人番号（`SIRO-`、`LUXU-` 等）全部按有码刮削**，它们是有码厂牌的正规番号。
> **Official 只出现在有码番号组，五个 `Official·...` 无码官网只出现在无码番号组**，国产传媒、欧美视频、个摄番号、国产短剧四组都不含它们——Official 按番号前缀路由到有码片商官网，对国产/欧美/个摄番号没有收录；五个无码官网只收无码番号，短剧又没有番号可路由，加进去只会给每条影片白挂一次无效请求。Dahlia、Faleno 是从 Official 拆出的有码厂牌独立站，只随**有码番号**一组走（素人线作品现已并入有码组一并刮削）。五个无码官网各自独立启用/禁用，禁用其中一个不会影响其他四个，也不会影响 Official。
> **AVEntertainments 只在无码番号一组**（2.5.6 起从有码番号、素人番号两组移除）：该站是正規無修正 DVD 販売/配信的商城，只收录无码番号，有码厂牌的番号查不到条目——放在有码番号、素人番号两组里只会给每条影片白挂一次请求，故只保留在无码番号组。爬虫本身不变（它仍在「编辑网站」候选区里可选，只是不被这两组默认勾选）。
> **MyWife 是独立系列，既不属于「有码番号」也不属于「国产短剧」，七组名单里都没有它**：MyWife（舞ワイフ）是「人妻・熟女・3P」这一条独立系列线——它不是有码厂牌的片商编号、也不落无码／个摄／欧美／国产任何一类，所以**有码番号组（28 站）不含它、国产短剧组（1 站）同样不含它**，两个表里都查不到 MyWife。**它走的是「单独指定」而非类型组**：「网站偏好 → 指定网站」选了 MyWife、或文件路径里含 MyWife 时，`mdcx/core/file_crawler.py` 返回 `ScrapeClassification(FixedScrapingType.YOUMA, "auto", website=Website.MYWIFE)`——番号形如 `MyWife No.1230`，不属于任何已知前缀体系，故借用有码的类型判定，但用 `website=MyWife` **覆盖**掉组内名单、直接锁定 MyWife 单站刮削，压根不查七组名单。故 `tests/test_config_conversion.py` 用 `Website.MYWIFE not in config.website_suren` 钉死它不会被误塞回短剧组；`Config().website_youma` 里同样没有它（历史配置里若残留过，也只会因不在类型组而从不生效）。
> **`Javlibrary·镜像` 排在 `JavLibrary` 后面（有码番号组里）**：原站 `javlibrary.com` 对中国大陆 IP 常年挂 Cloudflare 墙（要过 JS challenge，触发 Selenium 兜底），镜像站没有这层墙，故把它做成**独立站点**而不是「换个地址的原站」，并默认排在原站后面——同一条番号两条路都通时，先走原站，原站过不了墙再退到镜像。爬虫逻辑整体继承 `JavLibraryCrawler`（搜索、详情解析、封面升级都一样），差别只有三点：默认抓**中文页 `/cn`**、站点地址从 `https://zlibz.com/` 右上角公布的那张图里认（`mdcx/base/web.py` 的 `get_javlibrary_mirror_domain()`，带 24 小时缓存），以及有用户自定义网址时按用户填的走。**它与原站 `JavLibrary` 组成一个联动组**（`SITE_GROUPS` 第七组）：加入组内任意一个站点即自动带上另一个——两条路是同一份数据，原站撞上 CF 墙时镜像能顶上，只勾一条不如两条都留着；仍可在「启用网站」里单独移除其中一条。
> **镜像地址是「认图」而不是「读字」**：`zlibz.com` 主页把地址排成一张 `text.gif` 位图挂在右上角，HTML 里**没有任何文字形式的地址**（`/text.txt`、`/domain.txt` 之类端点全部 404），GIF 内部也没有注释块可读，页面上那张二维码图只解出 `http://zlibz.com` 本身。所以程序取到那张图后用**内容 sha256 查表**（`_JAVLIBRARY_MIRROR_IMAGE_HASHES`）认出它对应哪个地址；**换了图（表里没有的哈希）就退回「依次探测已知镜像域名列表」，再不行用列表首个**（`www.f101w.com/cn`）。也就是说官网换域名时程序仍能工作，但新地址要等表里补一条哈希才会被直接认出来。
> **同一份名单也是「编辑网站」对话框里「可用网站」候选区的分组依据**（`TYPE_DEFAULT_SITES` 一个常量两处用，界面与默认行为不会漂）：打开「设置→刮削网站 → 类型刮削网站 → 编辑网站」，左侧候选区**开头就是七个加粗的分组标题**——`有码 ｜ 无码 ｜ 个摄 ｜ 欧美 ｜ 传媒 ｜ 短剧 ｜ 动漫`（**短名**，只在这一处用短名：七个 chip 必须挤在同一行，带「番号」三字会顶到框宽；`个摄`/`传媒` 是 2.6.0 起按用户口径改的称呼，与设置页的「个摄番号」「国产传媒」同义），从左到右排列，**紧接着右边就接着铺全部可用站点**。标题与其它站点一样是普通的一格，**底色不额外加深、只是文字加粗**，后面不留空白、也没有单独一行，所以首行看起来就是 `有码 无码 个摄 欧美 传媒 短剧 动漫 7mmtv Airav.cc AVBase …`。**标题之下是一份去重后的 A-Z 名单**（`7mmtv` 到 `Xcity`，共 44 个站），同一站点只出现一次，七组之外的站点（`MyWife`、`AVSEX`）也在里面、**没有单独的「其他」分组标题**（它不在这七个类型里，但仍可正常勾选；由于每个站只出现一次，「它属于哪些类型」要看悬停提示）。站点行的悬停提示**只有一行 `<定位>：<类型名单>`**（如 7mmtv 为「综合：有码/无码/欧美/传媒」、AVSOX 为「无码：无码」、Madou.club 为「国产：麻豆」，冒号前的定性词沿用各站自己的定位说明，冒号后的名单由 `TYPE_DEFAULT_SITES` 现算、**次序跟上面那七个标题的组序一致**——不再用爬虫 `description` 里那句写死的文案，那句会与实际默认名单对不上，7mmtv 说明里就没有欧美、国产；**名单里不写「动漫」「个摄」**，动漫与其它类型的片子混在一站时不必单列，个摄（即原来的 FC2 组）同属有码那一类；**「短剧」则照常显示**——它只有 JavDay 一站，但正因如此更需要看得见——候选区那七个 chip、设置页各行标签与默认名单不受影响）。分隔符统一用 `/` 而非顿号，省宽度、悬停框不易折行；原先的「类型：…」「联动：…」两行已整行删掉（第一行已把类型名单说全，后两行是同一件事的重复）。**同一行也拼进三个站点下拉框的选项显示文本**（下拉框的悬停提示按用户要求只保留「上次检测：…」，不再重复能力文案）。不属任何类型组、或名单被隐空的站（`MyWife`、`AVSEX`、`Getchu`、`FC2`）改用它自己的定位说明一行。**双击某个标题即把该组全部网站按组内优先级顺序加入右侧「启用网站」列表**（组内顺序即上表的优先级顺序，联动组会自动补齐；**单击标题什么也不加**——七个标题挤在首行，顺手扫过必然挨个碰过去，一点就整组塞进去且无从撤销不是用户要的）；站点行的单击只是选中，加入靠双击站点或「添加选中」。右侧「启用网站」列表不受分组影响，顺序仍完全由用户拖拽决定。**两个列表都支持右键**：点站点复制该站名，**点某个标题复制它自己那一份名单**（如「有码」得 28 站，点「个摄」得 12 站、「动漫」得 4 站，互不相等），点空白处复制整张列表（逗号分隔，与对话框上方输入框同格式，可直接粘回去比对或增删）。候选区的右键菜单**最下方**另有「加入列表：启用网站」（与双击同一套逻辑）：点标题加入整组、点站点加入那一个、点空白处加入当前选中的那些；「启用网站」列表与「字段优先级」那几行没有这一项。**右键站点时，菜单最上方还会先列「启用站点：X」「禁用站点：X」两条**（在「复制站点：X」之上）：已禁用时「启用站点」可点、「禁用站点」置灰，未禁用时反过来；点一下立即生效，候选区与右侧「启用网站」列表里该站同步变灰，悬停提示追加「已禁用：自动刮削、网络检测、图片兜底跳过；指定网站/单文件/重新刮削仍可用」，但仍可选中、拖拽与移除。禁用状态是**七个类型组共享的一份全局名单**（`Config.website_disabled`，默认空列表即全部启用），在有码里禁用，无码、个摄、欧美、传媒、短剧、动漫与候选区一起变灰；每次启用/禁用后立即写入配置，不需要再点「保存」；点「取消」也不会回滚已经切换的禁用状态。被禁用的站不会进入自动刮削、网络检测与图片兜底；但用户明确指定该站时（指定网站模式、单文件、重新刮削）不受禁用名单影响，仍会正常请求并返回结果。重新启用后恢复原来的优先级与字段来源。

### DMM 官方高清直链

- 封面/海报统一走 DMM 官方 awsimgsrc CDN 高清直链（竖版 `ps` 通常 1032×1469，部分系列为 745×1081 等中尺寸档；横版 `pl` 通常 2184×1469），由 `mdcx/crawlers/dmm_direct.py` 的番号→DMM cid 前缀映射生成，内置静态前缀表覆盖约 110 个主流系列（含 `h_xxx`/数字特殊前缀与跨厂商附加前缀），并叠加学习表自动扩充未收录系列的前缀。升级时校验分辨率宽≥700 过滤 147×200 缩略图占位图，避免把海报覆盖成低清缩略图。
- **LibreDMM / R18.dev / JavBus / JavDB / JavDB API / JavDB App / DMM / DMM API / JavLibrary / AVBase** 十个爬虫在刮削时直接把返回的低清封面/海报升级为 DMM 高清（R18.dev 的 `jacket_full_url` 是 pics.dmm.co.jp 低清且部分系列 cid 未补零，JavBus 是自家 CDN 低清镜像，DMM/AVBase 用域名替换 + dmm_direct 前缀表候选），无码番号自动跳过。
- **JavDB 系图源无水印升级**：JavDB / JavDB API / JavDB App 三站产出/落回的 javdb 图床图片，下载时自动改走 JavDB App 专用 CDN `tp.spfcas.com` 无水印原图（加密流下载层透明解密），替代带 javdb 水印的网页版 CDN；App CDN 路径中段由 JavDB_APP 响应自动学习，失效时自动回退网页版。DMM 升级链覆盖不到的番号（无码/FC2/老片等）落回 javdb 图源时受益。
- 开启「Poster 选优」（poster_auto_best）时，候选池自动注入 DMM 竖版高清候选，按尺寸自动胜过低清原图，其他爬虫也能受益。
- DMM 图下载失败按「设置→网络→重试」次数（默认 3 次）自动重试，应对 awsimgsrc 偶发的连接抖动。

### 多网站结果合并

多个爬虫返回的数据会按字段优先级合并。比如标题优先取 JavBus 的数据，简介优先取 DMM 的数据——每个字段都可以独立配置优先级。

字段优先级对话框中每个字段行还可勾选「跳过」：勾选后该字段不从任何来源抓取（保持 NFO 中的既有值），适合某些字段想全部手动维护、不被刮削结果覆盖的情况。按刮削类型（有码/无码等）可分别设置。

## 二、六种刮削模式

### 1. 正常模式（全新刮削）

从头到尾走一遍：扫描文件 → 刮数据 → 下图片 → 生成 NFO → 重命名 → 移动文件。

适合新下载的视频。

### 2. 整理模式（读取 NFO 重新整理）

不联网刮削、不下载图片、不生成或更新 nfo：软件读取视频或 STRM 同目录同名 nfo 中的字段，再按照「设置→命名」中的目录名、文件名、字段、长度、马赛克、分集、图片、预告片、画质等命名规则，重新组织并移动视频/STRM、图片、nfo、字幕等文件。正常模式的字段来自网站刮削、图片从网站下载；整理模式的字段来自本地 nfo，图片已经在本地，只需随视频一起移动。同番号的 `-mediainfo.json`、种子、bif、预告片和剧照等关联文件也会一并移动，图片只移动、不二次加水印。

适合已经刮削整理过、只想按新的命名或目录规则重新归类的人；需要海报墙时同样适用，已有图片会跟着文件一起移动。**与「更新模式」的区别**（整理模式离线、更新模式必须联网，两者目录规则与搬运范围也不同）见下文「更新模式 vs 整理模式」对比表。单批数量复用「设置 → 高级 → 连续刮削」的配置，一批全部完成后再继续下一批；成功/失败输出目录与排除目录复用「设置 → 刮削目录」。每个番号按“全有或全无”直接移动：任一关联文件移动失败时先回滚并保留在原目录，该番号进入待重试队列；等其他番号全部处理完成后，再统一用管理员权限对失败番号重试一次，重试成功补记成功，仍失败才记为整理失败；缺少有效 nfo 的文件会被跳过并在日志中提示。

已经在「成功输出目录」里的文件（上一轮整理的产物）不再重复移动：这类文件按读取模式处理，只读取同目录 nfo 展示结果，左下角状态行会相应显示为「读取模式」。

目标目录已经有同名文件时怎么处理，由「设置 → 高级 → 移动文件」的「覆盖旧文件 / 保留旧文件」决定（两者互斥、必须勾选其中一个，默认勾选「保留旧文件」），详见下文「文件移动策略」。

设置→高级→高级功能下「任务模式」有两枚互斥选项：**本地存储文件**（默认，整理模式不设置时间间隔整理文件，随时可以开始整理）与**网盘存储文件**（整理模式按「设置→高级→间歇刮削→自动休息」设定的间隔整理，两次整理之间至少间隔自动休息时间，不足则自动等待到间隔满足后再开始整理，防止网盘目录缓存未刷新导致整理失败）。两枚必须勾选其中一个（默认「本地存储文件」），保存时校验归一，手改配置两开时保留更安全的「网盘存储文件」。网盘挂载成本地目录时目录缓存刷新有延迟（CloudDrive2 默认 40 秒、OpenList 默认 30 分钟），间隔太短会导致整理失败，因此「自动休息」最小值为 40 秒。旧整理模式的两枚独立 bool 键（`organize_local_no_interval` / `organize_netdisk_rest_interval`）已废弃，升级时自动迁移到 `switch_on` 任务模式开关组。

### 3. 分离模式

视频与元数据分开存放：刮削、下载与正常模式相同，视频文件按视频命名规则移动，图片/nfo 等元数据按单独配置的元数据目录规则移动。

搬移伴生文件时与正常模式共用同一套「番号 ↔ 伴生文件」归属索引 + 事务：只搬属于当前视频/STRM 的文件（同目录其它番号的图片、nfo、剧照目录不会被端走），主图/剧照目录落数据目录、字幕/种子/bif/json 跟视频目录，任一文件搬移失败整体回滚。

适合视频库与元数据库分开管理的场景。

分离模式还可以为本地视频生成 STRM 链接文本：勾选「覆盖本地已存在的STRM链接文本」时会**自动同时勾选**「为本地视频文件生成STRM链接文本」——没有生成 STRM 文件就无从覆盖；反过来取消生成时覆盖选项会一并取消。

### 4. 视频模式（仅整理文件）

只刮番号用于命名，然后重命名和移动视频文件。**不下图片、不生成 NFO**。

适合不想弄海报墙、只想把文件按番号归类的人。

目标目录已经有同名文件时怎么处理，由「设置 → 高级 → 移动文件」的「覆盖旧文件 / 保留旧文件」决定（两者互斥、默认都不勾选），整理模式同样复用这个选择，详见下文「文件移动策略」。

#### 视频模式固定删除伴生文件

视频模式只保留视频本体：视频按番号重命名、搬到新目录之后，原目录里**属于这个
视频/STRM 的伴生文件会被删除**——图片、剧照、剧照副本、预告片、主题视频、
NFO、JSON（含 `-mediainfo.json`）、字幕、种子、bif 等。

（旧版本的两个互斥选项「删除本地已下载的图片和信息文件」「移动已下载图片和文件
到新目录」已删除：视频模式的字面意思就是只整理视频，留着伴生文件反而让原目录
变成半空的残留目录。）

删除范围由**「番号 ↔ 伴生文件」归属索引**决定，与整理模式同一套判定：

- 归属索引在**任何文件被搬走之前**建立（媒体已搬走 → 归属丢失 → 会误判成别人的）；
- 只删归属当前视频/STRM 的文件；同目录里属于其它番号的文件、以及归属不明的
  共用文件（多番号混放时无法判定归属）**一律不动**；
- 系统目录（`@eaDir`、`#recycle`、`$RECYCLE.BIN`、`System Volume Information`
  等）不进索引，绝不参与删除；
- 清空后的剧照/预告片目录一并收掉（只删空目录）；
- **软链接/硬链接模式不删**：原目录里的视频本体还在，删掉伴生文件会把源目录掏空；
- 索引建立失败时退回按固定路径清理（图片、NFO、剧照目录、主题视频、预告片）。

#### 视频模式结束后的空目录清理

视频模式把所有任务跑完后，会把**本次确实被搬空**的原目录删掉——视频搬走、伴生文件删光之后，原目录往往就空了。

- 只删**扫描目录之内**、且删完就彻底空掉的目录；**扫描根目录本身永远保留**，根目录之外的目录也不动；
- 目录里还剩任何文件（或子目录）就停手，不会连着删非空目录；
- 这一步是「本次搬空」的定向收尾，**不受通用「删除空目录」开关约束**；但勾选了「不删除文件夹」豁免项（`NoEscape.FOLDER`）时，一个目录都不会删。

### 5. 更新模式（联网二次刮削 + 更新规则改结构）

联网重新刮削已有视频，字段一律来自网站爬虫（本地 nfo 不作为字段来源），流程与正常模式相同；区别只在于**命名与目录结构改按「更新模式规则」执行**，而不是套用「设置 → 命名」的完整规则。

适合已经刮过、想**联网补一遍最新信息**并顺手按 A/B/C/D 模板微调目录层级的场景。

「更新模式规则」提供 4 种目录操作（固定 A/B/C/D 四层）：

| 选项 | 结果 |
|------|------|
| 只更新C | 只改文件名，目录不动：`.../A/B/C[NEW].mp4` |
| 更新B和C | 改所在目录名与文件名：`../A/B[NEW]/C[NEW].mp4` |
| 更新B和C + 同时更新A目录 | 连上层目录一起改：`../A[NEW]/B[NEW]/C[NEW].mp4` |
| 创建D目录 | 在视频所在目录下新建一层：`.../A/B/D/C[NEW].mp4` |

#### 更新模式 vs 整理模式（两者最容易混淆，务必分清）

| 对比项 | 整理模式 | 更新模式 |
|--------|----------|----------|
| 字段来源 | 本地 nfo，**完全离线** | 网站爬虫，**必须联网** |
| nfo | 只移动，不生成也不更新 | 按「下载 → NFO」重写 |
| 图片 | 只移动，不下载、不二次加水印 | 先把本地已有图**搬到**新目录，再按「下载 / 保留」开关决定是否**重新下载覆盖** |
| 命名规则 | 完整「设置 → 命名」（目录名、文件名、字段、长度、马赛克、分集、图片、预告片、画质） | 独立的 4 个模板（更新A目录 / 更新B目录 / 更新C文件 / 创建D目录），固定四层 |
| 目标位置 | 归集到「成功输出目录」后再套目录名规则 | **基于文件当前位置推导**（就地改结构，不进成功输出目录） |
| 搬运范围 | 视频/STRM、nfo、全部同番号图片（含 gif 等动图）、字幕、种子、bif、预告片、`-mediainfo.json`（一并改名）、媒体目录下的剧照/附件子目录（extrafanart、extarfanart、backdrops 等，含目录名非标准写法）整体搬迁 | 视频、字幕、种子、bif、预告片、poster/thumb/fanart 三张主图（jpg/png/webp/bmp/gif/avif 均支持，保留原扩展名）、nfo；同样按番号归属索引只搬属于当前视频的文件 |
| 失败处理 | 全有或全无：任一文件失败即整体回滚、保留在原目录，末尾再统一用管理员权限重试一次 | 全有或全无：伴生文件与视频走同一个事务，任一文件失败整体回滚（管理员重试仍只在整理模式） |

三个最容易踩坑的点：

- **必须联网刮削**：更新模式 100% 走爬虫重新抓字段，没有「只搬文件不联网」的开关。只想挪文件、不想重新抓数据，请用**整理模式**。
- **图片受「下载 / 保留」开关控制**：更新模式先把本地已有的 poster/thumb/fanart 搬到新目录，随后按「设置 → 下载」「设置 → 保留」的勾选决定是否重新下载覆盖——「保留」勾上就只搬不重下，勾了「下载」而没勾「保留」会联网重下并覆盖，两个都不勾则删掉旧图且不下载。剧照 extrafanart 同理。
- **目标路径基于文件当前位置，而非「成功输出目录」**：更新模式的 B 目录取视频当前目录的同级、A 目录再上一级；整理模式则把文件归集到「成功输出目录」再套目录名规则。两者选错位置时结果完全不同。
- **剧照目录按「媒体目录下的伴生子目录」识别**：整理模式不再只认 extrafanart 这几个固定名字。媒体所在目录下的子目录，只要目录名疑似剧照（含 fanart / backdrop / scene / trailer）或目录内没有视频文件，就会连同里面的图片整体搬走——写成 `extarfanart` 这种错别字也不会漏搬，且搬走时**目录名会归一到标准名**（`extarfanart` → `extrafanart`，`backdropss` → `backdrops`），已经是标准名或配置里自定义的名（如 `extrafanart_copy`）保持原样。目录内的 gif 动图同样会搬走；标题目录下的 gif（fanart.gif、thumb.gif 等）也按原文件名搬运，不会被改名成 poster.jpg / fanart.jpg。
- **poster / thumb / fanart 支持其它图片格式**：三张主图不再只认 `.jpg`——本地已有的 `.jpeg` / `.png` / `.webp` / `.bmp` / `.gif` / `.avif` 同样会被识别为主图，**搬走时保留源文件的真实扩展名**（`poster.png` → `poster.png`，`fanart.gif` → `fanart.gif`），不做「改扩展名」的格式伪装，动图也不会被压成静图。整理模式与更新模式（普通/更新）都生效：更新模式把旧目录里的 `poster.png` 搬到新目录后同样是 `poster.png`，刮削收尾时记录的封面路径也跟着指向真实文件。若同时存在 `.jpg` 与 `.png` 两份，以 `.jpg` 为准、另一份作为普通图片一并搬走，下载覆盖后残留的旧格式副本会被清理干净，不会出现两份同图并存。

另外：整理模式强制不跳过「已刮削成功」的文件，更新模式则遵循「跳过之前已刮削成功的文件」勾选（默认不勾 = 不跳过）。混用两个模式时容易出现「更新模式报 0 个文件」的错觉。

### 6. 读取模式

只做一件事：读取视频 / STRM 同目录同名 nfo 中的字段，以及目录里的封面图（poster）、缩略图（thumb）、背景图（fanart），在界面展示结果。**不联网、不下载、不写 nfo、不移动也不重命名任何文件**，适合检查媒体库、核对已刮削的信息与图片；没有同目录同名 nfo 的文件会跳过并在日志里写明原因。读取模式不受断点续刮缓存影响，每次都处理全部选中文件。

原先挂在读取模式下的「按更新模式重新整理分类 / 重新下载封面 / 允许更新 NFO / 无 NFO 按正常模式刮削 / NFO 合并及策略」五个选项，已整体迁到下面的**补全模式**。

### 7. 补全模式

面向「已经刮削过、但部分文件缺字段或缺图」的媒体库，核心是**本地已有优先，只补缺失**：

- 先读取视频 / STRM 关联的 nfo 字段；本地有值的一律保留，只把空着的字段用联网刮削结果补上（未勾选「本地NFO合并及策略」时固定「本地信息优先」）；
- 番号 / 演员 / 标题 / 封面图 / 缩略图 / 简介 / 标签 / 日期 / 时长 / 导演 / 系列 / 制作 / 发行 这 13 项都已有具体值时，**不再联网**：直接沿用本地 nfo 走完流程并计入成功列表（空白、`null` 之类的占位文本算缺失，封面/缩略图认本地已存在的图片文件）；
- 简介占位值会被清空并去其他站点重新获取：nfo 里写成「发行日期 2025-11-13」（各种日期变体）或「看更多」的内容不算简介，取不到真简介就保持为空，绝不回填；
- 封面图 / 缩略图 / 背景图：本地已有就保留，缺哪张补哪张，不会重复下载、也不会重复打水印；勾选「本地NFO内有链接，重新下载封面图片等文件」才回到正常模式的下载语义；
- 字幕：视频没有外挂字幕时，从「设置 → 字幕 → 添加外挂字幕 → 字幕存放目录」按同番号 / 同名查找，复制到刮削后的文件夹；
- 没有 nfo 的文件自动切换到正常模式全量刮削（下载图片、写 nfo、按正常模式规则命名）；
- 已在「成功输出目录」内的文件只补字段与缺失的图片/字幕，不移动、不重命名；不在目录内的文件按「刮削成功后移动 / 重命名」开关处理，搬运复用整理模式的事务：伴生文件先落位、视频/STRM 最后搬，任一文件失败整体回滚到原目录；结束后同正常模式删除空目录；
- 与正常模式的唯一区别：正常模式是全量重新刮削（新数据会覆盖本地 nfo），补全模式是本地优先、刮削只填空字段。

下方两个选项 + 合并策略：按更新模式重新整理分类（走 A/B/C/D 更新规则）/ 重新下载封面图片（勾选后本地已有的图也会重下并重新打水印）/ 本地NFO合并及策略（三档，默认「仅填补空字段」）。「允许更新 NFO 文件」「无 NFO 时按正常模式刮削」两项已删除——前者由「补到空字段即写回」取代，后者本来就无条件执行。补全模式同样不受断点续刮缓存影响，可以反复运行把缺失项补齐。

### 文件移动策略（整理模式 / 视频模式共用）

「设置 → 高级 → 移动文件」有两枚互斥的复选框，决定**目标目录已经有同名文件**时怎么办，**必须勾选其中一个**（默认勾选「保留旧文件」），保存配置时会校验：万一两枚都没勾（手改配置文件等异常），按默认档「保留旧文件」校正后写盘：

| 选项 | 作用 |
|------|------|
| 覆盖旧文件 | 用被移动文件**直接覆盖**目标目录里的同名文件（不留冲突副本） |
| 保留旧文件（默认） | **保留**目标目录里的同名文件不动，被移动的文件**留在原目录不移动**（不覆盖、不删除任何一方） |

- 该选择只对**整理模式**与**视频模式**的移动生效，其它刮削模式维持原样（目标同名仍然报错中止）。
- 「保留旧文件」是**整单生效**的：目标同名时，本次番号的视频与伴生文件（图片、nfo、字幕等）**全部留在原目录**，避免视频与图片/nfo 被拆散。
- 「覆盖旧文件」同样是**事务式**的：覆盖前先把目标文件备份，搬运失败会**回滚**（目标文件恢复原内容、源文件回到原目录），全部成功才提交（此时才真正丢掉旧文件）；整理模式末尾的「校验目标文件是否存在」也照常生效。
- 配置写在配置文件的 `switch_on` 列表里：`move_keep`（保留旧文件）与 `move_overwrite`（覆盖旧文件），两者互斥；老配置升级时自动补上默认档 `move_keep`。

## 三、NFO 文件生成

生成 Emby/Jellyfin/Kodi 通用的 .nfo 文件，包含 30+ 字段：

- **基本信息**：番号、标题、原始标题、简介、标语
- **发行信息**：发行日期、年份、分级、国家
- **人员**：演员（多语言名称）、导演、演员 TMDB ID
- **评分**：公众评分、影评人评分、想看数
- **分类**：标签、类型、系列
- **制作**：制作商、厂牌、发行商
- **媒体**：海报 URL、缩略图 URL、背景图 URL、预告片 URL
- **外部 ID**：各网站 ID（javdbid、javlibraryid 等）

写入时可通过 **NFO合并**（补全模式区域勾选框+下拉框，3 选 1）控制如何处理已存在的 NFO 文件：勾选后按所选策略合并——全新数据优先（等于正常模式的覆盖行为）/ 合并数组去重 / 仅填补空字段（默认：本地已有值一律保留，只把本地空着的字段用刮削值补上）；不勾选则直接用新数据覆盖、不合并本地 NFO 文件，防止重刮覆盖手动整理的内容（如手改的简介、标签）。旧的「本地信息优先」「保留已有字段」两档已并入「仅填补空字段」，旧配置自动升级。

### 下载

### Amazon 高清封面

从 Amazon 搜索高清封面图（1500px 尺寸），支持：

- 三层搜索策略：条码快路径 → 标题搜索 → 演员名称兜底
- ASIN 数据库缓存（Excel 保存，避免重复搜索；写入按番号去重，同番号不重复入库；出厂库随版本更新，老用户启动时自动按番号合并新增/补全空缺，不覆盖用户已填值；合并产生新增行时按番号整体重排）

当前 Poster 已是 DMM 官方 awsimgsrc 高清图（宽≥700）时按分辨率直接放行、跳过日亚搜索——DMM 竖图普遍只有 170-420KB，原 400KB 字节阈值会误判为「不够清晰」而误走昂贵的日亚搜索；DMM 缩略图（147×200）与窄图仍会被拦截继续走日亚。

### 海报超分（实验性）

对最终落盘的海报做 AI 超分辨率放大补清（Real-ESRGAN 4x / waifu2x 2x 两档预设），仅当海报最长边低于阈值（默认 800px）时触发：
- 工具为 Real-ESRGAN、waifu2x 官方预编译的 ncnn-vulkan 二进制，非内置模型推理，无 torch/ONNX 依赖
- 获取方式随打包形态而定：Windows / Linux 打包版内置，首次使用时释放到 `userdata/sr/tools/<tool>/`；macOS 打包版与源码运行首次使用时从 GitHub Release 下载（约 30-60MB，仅一次）
- 下载后按内置 sha256 基准校验，不符即判该源失败，避免拿到被替换的可执行文件
- 需支持 Vulkan 的 GPU（Intel 集成显卡需第 6 代酷睿及更新）；缺失 Vulkan、下载失败、超时一律静默保持原图，不影响刮削结果

### 官方图源兜底（DMM / MGStage）

当所有图源站点均无法获取封面/海报时，按番号直构官方 CDN 高清图兜底（设置 → 下载「下载高清图」组可开关，默认开启）：
- **DMM**：直构 awsimgsrc 高清封面（横版），自动学习厂牌前缀：
  - 从刮削过程中观察到的真实 DMM URL（高清封面升级命中 + dmm 爬虫验证过的图）提取「系列 → 前缀」证据
  - 状态机管理：≥2 个不同番号验证成功转正（verified）、连续构造失败 ≥3 次隔离（quarantined）、新证据解除隔离重新验证
  - 学习数据持久化到 `userdata/dmm_prefix_learned.json`（原子写），仅记录验证成功的证据
  - CID 候选构造顺序：学习表 verified → 静态前缀表 → 学习表 provisional → 常见前缀盲试
- **MGStage**：站点图源全部失败时，直构 MGStage 官方 CDN 高清图——`pb_e` 横版大图（840 宽，高度随片源比例约 470~560）作封面兜底、`pf_e` 竖版小图（422×600）作海报兜底（系列映射表：LUXU/OTIM/CHUC/GERK/ONEZ/ONEX/MFC/ARA，来自 JavDB 高清图替换油猴脚本实测并经多番号实测验证），补上 DMM 不收录的素人番号场景
- 所有图片下载统一设 50MB 大小上限，防止异常大文件占用磁盘

- **补全封面图片工具**：输入番号，多个用空格分隔，自动刮削并补齐缺失的Poster.jpg和Thumb.jpg，复用当前配置的站点优先级、命名、裁切、水印规则，所有站点拿不到图时自动走DMM官方高清直链兜底，内置约110个主流系列前缀表并自动学习未收录厂牌，竖版高清图片优先，无码番号跳过。
- **演员数据维护工具**：直接操作 `actor_database.xlsx`，一键补全中文名、LibreDMM 链接、别名（可选来源 TMDB/minnano/JavDB，默认仅补缺别名行，可全量并入，支持起始行/限量分片续跑）、JavDB 中文名（从 JavDB 移动端 API 查询演员中文名/繁体名，无需 TMDB API KEY）、minnano 补全、检查用户库（扫描+自动修复安全项）、剔除男演员、校验 tmdbid 有效性、更新 nfo tmdbid、打开数据库查看编辑（复用当前配置的 TMDB API），并发请求日志实时显示
- **网络连通性检查**：一键测试各网站可不可达
- **相似推荐**：在右侧结果树中对任意影片右键→「查看相似片推荐」，基于标签IDF加权Jaccard相似度+系列/片商/发行商/导演/评分/年份/时长/演员等多维特征本地离线计算，自动推荐风格相近的影片，支持全部历史刮削结果含跨会话，双击推荐项可跳转
- **命令行刮削**：`uv run crawl` 在终端中调试爬虫

## 十一、断点续刮与状态缓存

- **断点续刮**：刮削进度自动保存到WAL模式SQLite本地数据库userdata/scrape_state.db中，程序重启或崩溃后再次刮削，会自动跳过已完成的文件、恢复上次失败的未超限文件，最多自动重试3次，从上次进度继续，读取模式不受断点续刮缓存干扰，始终处理全部选中文件，如需清除缓存重新全量刮削，可使用「软件工具」页的「刮削缓存管理」重置。
- **失败重试**：刮削失败的文件自动记录，下次启动时重新尝试，连续失败3次后停止自动重试，届时可在结果树中对失败项右键「重新刮削」输入正确番号重刮或「输入网址重新刮削」指定详情页网址重刮，手动重刮不受重试次数限制。
- **读取模式不受缓存干扰**：读取模式（main_mode==5）始终处理全部选中文件，不跳过已完成的文件，不写入 done/failed 状态，确保维护操作覆盖完整
- **刮削缓存管理**：软件工具页刮削缓存面板可查看缓存统计（已完成/失败/总数）、刷新统计、导出缓存数据、重置缓存（清除已完成标记，下次全量重刮）、清空缓存（删除 scrape_state.db 文件）
- **结果摘要缓存**：刮削成功时存储相似推荐所需字段，供相似推荐跨会话使用
- **安全回退**：数据库损坏或不可用时自动回退内存模式，行为与无缓存一致
