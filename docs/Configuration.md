## 字段优先级

每个字段独立的来源网站优先级。

支持的字段共 19 项：标题、原始标题、简介、原始剧情、演员、所有演员、缩略图、海报、剧照、标签、发行日期、片长、评分、导演、系列、制作商、发行商、预告片、想看。

每个字段行还可勾选「跳过」：勾选后该字段不从任何来源抓取，保留 NFO 既有值。

还可以按刮削类型（有码番号/无码番号/个摄番号/欧美视频/国产传媒/国产短剧）分别设置不同的字段优先级。

### 海报超分

| 配置项 | 作用 |
|-------|------|
| `poster_sr_enabled` | 总开关，默认开启（对应设置项「海报超分」）|
| `poster_sr_preset` | 放大预设：`realesr-photo-4x`（Real-ESRGAN 4x）或 `waifu-photo-2x`（waifu2x 2x）|
| `poster_sr_max_dim` | 最长边小于此值才触发超分，默认 800px（1200 会把常见站点默认封面几乎全部纳入）|

工具的获取方式（由打包形态决定，不需要手动下载）：

- **Windows / Linux 打包版**：工具已内置在包里，首次使用时释放到 `userdata/sr/tools/<tool>/` 后使用。
- **macOS 打包版 / 源码运行**：首次使用时从官方 GitHub Release 下载（约 30-60MB，仅一次），校验 sha256 后解压到同一目录。

下载失败、无 Vulkan 环境或超时都只会静默降级保持原图，不影响刮削结果。也可以手动下载解压到 `userdata/sr/tools/realesrgan/` 与 `userdata/sr/tools/waifu2x/`（二进制名为 `<tool>-ncnn-vulkan[.exe]`，需与其 `models` 目录同级）。第三方工具许可见 `resources/licenses/sr/`。

| `{{ first_letter }}` | 番号首字符 |
| `{{ outline }}` | 简介 |
| `{{ director }}` | 导演 |
| `{{ series }}` | 系列 |
| `{{ studio }}` | 片商 |
| `{{ publisher }}` | 发行商 |
| `{{ release }}` | 发行日期 |
| `{{ year }}` | 年份 |
| `{{ runtime }}` | 时长 |
| `{{ mosaic }}` | 有码/无码标识 |
| `{{ definition }}` | 清晰度（1080p/HD 等）|
| `{{ cnword }}` | 中文字幕标识 |
| `{{ moword }}` | 无码流出等版本标识 |
| `{{ filename }}` | 原文件名 |
| `{{ wanted }}` | 想看人数 |
| `{{ score }}` | 评分 |
| `{{ four_k }}` | 4K 标识 |

条件渲染示例（扩展名由程序自动追加，不要写进模板）：
```
[{% if number %}{{ number }}{% endif %}]{{ title }}
```

三种命名目标：
- **文件夹命名**：`[{{ number }}]{{ title }}` 这种
- **文件命名**：`{{ number }}-{{ title }}` 这种
- **NFO 标题**：Emby 库中显示的标题

## 配置文件在哪

程序启动时会找一个叫 `MDCx.config` 的文件（和 main.py 同目录），这个文件里存的是当前启用的配置文件的绝对路径。配置文件是 JSON 格式（v2），如果发现旧版 INI 格式会自动转 JSON。

默认配置文件在 `resources/config/default_config.json`。

用户数据目录（演员数据库 `actor_database.xlsx`（日文原名/中文名/繁体名/别名/链接/tmdbid/tmdb url/出生日期/简介共 9 列）、Amazon ASIN 缓存等）在配置文件同目录的 `userdata/` 下。

## 旧配置会怎么被自动升级

程序启动读配置时会自动把**结构上不兼容**的旧配置升级成当前结构，**不需要手动改 JSON，也不需要重置配置**（重置会丢你自己的设置）。目前生效的只有「结构兼容」这一类改名与换算：

| 升级内容 | 规则 |
|-----|------|
| **站点名** | 旧站点名自动改成现在的名字（如 `javdbapi` → `DMM_API`、`faleno` → `Faleno`）；已经下线的站点会被自动剔除 |
| **内置命名模板** | 旧式的 `{number}` 写法自动换成 Jinja2 的 `{{ number }}` 写法 |
| **代理地址等杂项** | 早期写法的值自动规整成现在的形式（如没写协议的代理补 `http://`） |
| **刮削模式编号** | 2.2.3 起「分离模式」插到了第 2 位，视频/更新/读取顺延为 3/4/5。老编号的配置会被换算（你选的模式本身不变：旧 2 = 视频 → 新 3 = 视频，以此类推）。**只换算一次**——判据是「配置里有没有分离模式的四个开关」（与版本号无关，见下一节），换算过就不再来第二次 |

升级提示会以 `[迁移]` 开头的形式出现在日志里，例如「刮削模式编号已调整……」。这类提示只是**告知**，不是错误——配置本身仍然是加载成功的。

⚠️ **两条要知道的限制**：

1. **缺失的配置项不会自动补齐。** 旧配置里整个键都没有的项，程序运行时会用内置默认取值，但你打开 `config.json` 看到的仍是缺字段的旧样子。同样地，「下载文件」这类列表里出厂默认新增的选项**不会**自动补勾上——需要你手动加上，或在设置页重新勾选后保存。
2. **升级结果不会自动写回磁盘。** 只有你在设置页正常保存配置时才会落盘。所以升级效果只在本次运行内有效，下次启动会重跑一遍同样的升级。

## 配置版本号 `config_version` 恒为 2

**`config_version` 永久固定是 `2`，任何情况下都不会再变。**

- 新增配置项、新增列表选项、给旧配置补缺键——**不变**；
- 哪怕以后真的改了配置的整体结构（比如再加一种刮削模式）——**照样不变**；
- 你手上还是 `3` 的老配置，启动后会被自动写回 `2`，之后就一直是 `2`。

**不要靠比对版本号来判断配置新旧**：版本号不承载「配置落没落伍」这个信息，它就是个常量。看到别人的配置是 `2`、自己的也是 `2`，并不代表两份配置一样新。**判断配置是否最新，只看 `config.json` 里有没有缺字段**——而缺字段目前**不会**自动补齐（见上一节的限制）。

这条纪律对程序本身也是硬约束：`mdcx/config/migrations.py` 的 `CURRENT_CONFIG_VERSION`、`Config.config_version` 的默认值、`resources/config/default_config.json` 三处必须始终一致；`tests/test_config_conversion.py::test_config_version_frozen_at_two_everywhere` 会钉死这一点，以后谁想「顺手升一下版本号」，测试直接红。

⚠️ **为什么「版本号固定为 2」必须配套改掉迁移判据**：刮削模式编号换算原本拿「版本号 ≥ 3」当「已经是新编号」的判据，而版本号冻结成 2 之后这个条件**永远不成立**，于是每次启动都会把已经是新编号的配置再迁一遍（分离模式 2 → 视频 3 → 更新 4 → 读取 5），你的刮削模式会被悄悄改掉且越用越偏。现在判据换成了**结构性**的「配置里有没有分离模式的四个开关」（`separate_success_file_move` / `separate_failed_file_move` / `separate_success_file_rename` / `separate_del_empty_folder`）——它们与新编号是同一批入列的，新编号配置必然带、旧编号配置必然没有，所以只看键在不在，和版本号是多少完全无关。

## 配置升级时会发生什么

**版本号只管「结构语义」，不管「配置落没落伍」**。所以升级配置时按这几条来，不要看版本号：

| 你的配置状况 | 会发生什么 |
|-----|------|
| 结构是旧的（不兼容） | 自动升级到当前结构，例如站点改名、内置命名模板换写法、刮削模式编号换算——**你选的模式本身不变** |
| 缺配置项 | **不会自动补**。程序按内置默认取值，但文件里仍是缺字段的样子，要补齐请在设置页保存一次 |
| 列表里少了新选项 | **不会自动补勾**，需要你手动加上或在设置页重新勾选 |
| 有读不出来的非法项 | **照样出现在「当前配置」下拉框里**，不会被藏起来，由你自己改 |

注意升级结果**不会自动写回 `config.json`**——只有你在设置页保存配置时才落盘。

## 「当前配置」下拉框

设置页和工具页各有一个「当前配置」下拉框，里面列出**配置目录下的每一个 `.json` 文件**（`.ini` 是 1.0 时代的旧格式，早已废弃，不会出现在列表里），你可以随时切到其中任意一份。它**不会**因为某份配置读不出来、缺键或版本旧就把那份藏起来——加载失败时程序会先切到 `_failed.json` 保护你原来的配置不被覆盖，而这个下拉框正是你切回去的通道，藏起来等于把你锁死。

你可以把多份配置放在同一个目录里并存，按用途区分命名（例如按不同的命名方式、不同的刮削网站各存一份），想切哪份切哪份。

## 「重置配置」会清掉我的配置吗

会。「重置配置」是把整份配置**覆盖**成出厂默认值，`api_key`、各类 Cookie、ThePornDB token、真实媒体路径等**全都会被清掉，且无法从软件内恢复**。

程序现在会在覆盖前**自动备份**一份 `xxx.resetbak-<时间戳>.txt`（与配置文件同目录），按时间倒序只保留最近 10 份。备份刻意用 `.txt` 而不是 `.json` 后缀——否则会被「当前配置」下拉框当成真配置列出来。要找回就打开对应时间戳的 `.txt`，对照着改回 `config.json` 即可。

## 翻译功能需要填 LLM 密钥吗

**不需要。** 不填 LLM 密钥一样能正常打开软件、进设置页、正常刮削；只有真正要用 LLM 翻译时才会提示你去设置页填密钥，然后这一轮翻译跳过。密钥不是启动的前置条件。

## 已知问题：程序启动即崩（`RecursionError`）

**这是尚未修复的已知缺陷**，先说触发条件，因为它几乎都由人为改动引起：

如果你手动改过、或从别人那里拷来了 `MDCx.config` 这个标记文件，它里面记着「当前用的是哪个配置文件」。**这个路径一旦指向一个已经不存在的位置**（比如指向了系统临时目录 `%TEMP%\...`，而那个目录早被系统清理掉了），程序启动时会反复尝试重建它、越试越深，最后直接崩溃退出。

**自查与规避**：用记事本打开程序目录下的 `MDCx.config`，里面就一行，是你配置文件所在的完整路径。确认**那条路径下的文件确实还在**。如果路径是 `%TEMP%` 之类的临时目录、或者文件已经被删了，直接把这一行改成你实际配置文件的位置即可（例如 `D:\应用软件\工具软件\MDCx\default.json`）。

这个标记文件**不在升级范围内**（它不属于配置文件本身），换软件版本不会动它——所以搬目录、清理系统临时文件、或者从别人那儿拷配置之后，**要顺手确认一次它还指得对**。
