# 使用手册

日常使用 MDCx 会遇到的各种操作和问题。

## 界面说明

软件界面分成几块：

- **顶部**：工具栏（开始、停止、播放等按钮）
- **左侧**：导航栏（软件界面、软件日志、软件工具、演员管理、信息管理、软件设置、检测网络、使用说明）
- **中间**：主工作区（待刮列表、刮削结果树「成功/失败」、封面预览）
- **底部**：进度条和状态信息

设置界面通过左侧导航「软件设置」进入，分为 12 个标签页（刮削目录、刮削模式、刮削网站、下载、命名、翻译、字幕、水印、NFO、演员、网络、高级）。网站的连通性与可用状态在左侧导航「检测网络」页查看。

## NFO 文件管理

左侧导航「信息管理」页面用于浏览和批量编辑已刮削的 NFO 文件：

1. 点击「选择目录」或手动输入目录后回车，自动递归扫描生成文件列表
2. 顶部筛选框支持按番号/演员/标题关键词过滤列表
3. 点列表项读取 NFO，中栏表单可编辑番号、标题、演员、发行日、导演、制作商、系列、评分、简介、标签等 15 个字段
4. 右栏同步预览本地海报和缩略图，「裁剪封面」可调起裁剪工具
5. 点击「保存当前 NFO」时自动对比改动并弹窗确认（字段级 diff），无改动不写盘
6. 批量操作面板：列表顶部「全选/全不选」或 Ctrl+点击勾选多条后，一键替换演员名、加标签、删标签、统一系列名
7. 列表右键菜单：重新刮削番号（找同目录同名视频入队）、打开所在目录、删除NFO文件

## 基本操作流程

### 1. 配置刮削目录

设置 → 刮削目录：
- **待刮削视频目录**：放视频文件的文件夹
- **成功输出目录**：（可选）处理好后复制一份到另一个地方
- **软链接路径**：（可选）创建软链接的目标目录

### 2. 选网站源

设置 → 刮削网站：
- 按影片类型分别配置：有码番号、无码番号、个摄番号、欧美视频、国产传媒、国产短剧、动漫里番
- 每个类型可以选多个网站，拖动排序决定优先级
- **免 CF 通道**（JavDB_API、JavDB_APP、Missav_API、R18.dev、TheJavDB）默认已加入网站源，稳定性好可优先使用

### 3. 字段优先级

设置 → 刮削网站 页每个类型旁的「字段优先级」按钮：
- 每种字段（标题、简介、演员、海报等）都可以独立配置来源网站顺序，也可勾选「跳过」不从任何来源抓取
- 比如标题优先用 JavBus，评分优先用 DMM
- 每种刮削类型（有码番号/无码番号等）还可以有不同的字段优先级配置

### 4. 配置下载

设置 → 下载：
- 勾选需要下载的内容：海报、缩略图、背景图、剧照、预告片
- 人脸裁剪：开启后自动检测人脸位置裁剪海报
- Amazon 高清封面：从 Amazon 搜索高清图
- 官方图源兜底（默认开启）：图源全部失败时直构官方 CDN 高清图——DMM 高清封面（自动学习厂牌前缀）+ MGStage 素人高清海报
- JavDB 系图源自动无水印：刮削到 javdb 图床的封面/海报/剧照时自动改走 JavDB App 无水印原图（加密流透明解密，无需配置）

### 5. 翻译（可选）

设置 → 翻译：
- 选翻译引擎（Google / Bing 不需要配置，直接用）
- 选需要翻译的字段
- 可选启用简繁转换

### 6. 命名规则

设置 → 命名：
- 用 Jinja2 模板定义文件命名规则
- 常用模板：`[{{ number }}]{{ title }}`（扩展名由程序自动追加）
- 也可以单独设置文件夹命名和 Emby 标题展示格式

### 7. 开始刮削

1. 回软件界面，点「开始」，程序自动扫描刮削目录中的全部视频并开始并发刮削（新用户建议先用只放 1 个文件的目录试跑）
2. 看日志区跑进度，结果树的「成功/失败」列表随每个文件完成而实时更新
3. 刮完后处理失败项：右键「重新刮削」（输入正确番号重刮）或「输入网址重新刮削」（指定详情页网址重刮）

## 六种模式怎么选

| 你的需求 | 选哪个模式 |
|---------|-----------|
| 新下了视频，要完整的海报墙 | 正常模式 |
| 已刮削整理过，只想按新命名/目录规则重新整理，**不联网**、不重下图片 | 整理模式 |
| 视频和元数据要分开存放 | 分离模式 |
| 只要按番号归类视频，不要图片/信息文件；搬走视频后把该番号关联的图片、剧照、nfo、json、字幕等一并删掉（跑完自动清掉搬空的原目录） | 视频模式 |
| 已刮削过，想**联网重新刮一遍**补最新信息，并按 A/B/C/D 模板微调目录层级 | 更新模式 |
| 维护已有媒体库，补刮或更新 | 读取模式 |

### 整理模式 vs 更新模式（别选错）

两者都能「改名字 + 挪目录」，但底层机制完全不同：

| 对比项 | 整理模式 | 更新模式 |
|--------|----------|----------|
| 是否联网 | **完全不联网**，字段取自本地 nfo | **必须联网**，字段取自网站爬虫，nfo 也会被重写 |
| 图片 | 只移动，不下载、不二次加水印 | 先搬过来，再按「下载 / 保留」开关决定要不要重新下载覆盖 |
| 命名规则 | 完整「设置 → 命名」（目录名、文件名、字段、长度、马赛克、分集、图片、预告片、画质） | 独立的 4 个模板（更新A目录 / 更新B目录 / 更新C文件 / 创建D目录），固定四层 |
| 目标位置 | 归集到「成功输出目录」后再套目录名规则 | **基于文件当前位置推导**，就地改结构，不进成功输出目录 |
| 搬运范围 | 视频/STRM、nfo、全部同番号图片、字幕、种子、bif、预告片、`-mediainfo.json`（一并改名）、剧照目录整体搬迁 | 视频、字幕、种子、bif、预告片、poster/thumb/fanart 三张主图、nfo；同样按番号归属索引只搬属于当前视频的文件 |
| 失败处理 | 全有或全无：任一文件失败即整体回滚、保留在原目录，末尾统一用管理员权限重试一次 | 全有或全无：伴生文件与视频走同一个事务，任一文件失败整体回滚 |

一句话记法：**只想挪文件、不想联网 → 整理模式；想联网补数据、顺手调层级 → 更新模式。**

详细区别看 [Features.md](Features.md) 的「六种刮削模式」。

### 目标目录已有同名文件怎么办（高级 → 移动文件）

「软件设置 → 高级」页的「移动文件」有两个复选框，**必须同时选中一个，默认勾选「保留旧文件」**：

| 选项 | 作用 |
|------|------|
| 覆盖旧文件 | 移动文件时，如果目标目录已有同名文件，用被移动的文件**直接覆盖**它 |
| 保留旧文件（默认） | 移动文件时，如果目标目录已有同名文件，**保留目标目录里的旧文件**，被移动的文件**留在原目录不移动**（不覆盖、不删除任何一方） |

- 这个选择会被**整理模式**、**补全模式**的移动文件复用；其它刮削模式不受影响。
- 「保留旧文件」是整单生效的：目标同名时，该番号的视频和图片/nfo/字幕等伴生文件**全部留在原目录**，不会被拆散。
- 「覆盖旧文件」仍然有事务保障：覆盖前先备份，失败会回滚（目标文件恢复原样、源文件回到原目录），全部成功才提交。
- 点「保存」时会校验这两个框：**万一一个都没勾**（比如手改过配置文件），会自动按默认档「保留旧文件」校正后写盘。

选项会保存到配置文件里（`switch_on` 中的 `move_overwrite` / `move_keep`），老配置升级时自动补上默认档 `move_keep`。

### 任务模式：任务文件存储位置（软件设置 → 高级 → 高级功能）

「任务模式」下也有两枚互斥选项，**必须同时选中一个，默认勾选「本地存储文件」**，配置保存在 `switch_on`（`task_store_local` / `task_store_netdisk`），旧版整理模式的独立 bool 键已废弃并自动升级：

| 选项 | 作用 |
|------|------|
| 本地存储文件（默认） | 任务文件本地存储文件，整理模式不设置时间间隔整理文件，随时可以开始整理 |
| 网盘存储文件 | 任务文件网盘存储文件，整理模式按「高级 → 间歇刮削 → 自动休息」设定的间隔整理文件，两次整理之间至少间隔自动休息时间 |

- 勾「网盘存储文件」时会自动取消「本地存储文件」，反之亦然。
- 两枚都没勾（手改配置文件等异常）时保存会按默认档「本地存储文件」校正后写盘；两枚都勾时保留更安全的「网盘存储文件」校正（网盘目录缓存未刷新时整理会失败）。
- 网盘挂载成本地目录时目录缓存刷新有延迟（CloudDrive2 默认 40 秒、OpenList 默认 30 分钟），所以「自动休息」的最小值固定为 40 秒，确保整理间隔足够长。
- 点「保存」时同样会校验：万一一个都没勾，会自动按默认档「本地存储不设置时间间隔整理文件」校正后写盘。

### 分离模式生成 STRM 时，勾覆盖会自动带上生成（刮削模式 → 分离模式）

「软件设置 → 刮削模式 → 分离模式」下方有两枚 STRM 选项：

| 选项 | 作用 |
|------|------|
| 为本地视频文件生成STRM链接文本 | 为本地视频生成 `.strm` 链接文本（放在数据存放目录，与 nfo/封面同目录） |
| 覆盖本地已存在的STRM链接文本 | 已存在的 `.strm` 链接文本也重新写入（不勾则已存在的保留不覆盖） |

- **勾「覆盖本地已存在的STRM链接文本」时会自动同时勾上「为本地视频文件生成STRM链接文本」**：没有生成 STRM 文件就无从覆盖，所以这两枚是「覆盖 ⇒ 生成」的联动关系。
- 反过来取消「为本地视频文件生成STRM链接文本」时，「覆盖…」会一并取消（没有生成就没有可覆盖的）。
- 旧配置里若只勾了「覆盖…」没勾「生成…」，升级后会自动补上「生成…」让覆盖真正生效。

## 常见问题

### 安装和运行

**装 Python 依赖报错**：
```bash
uv sync --dev
```
如果报某个包找不到，先确认网络能连 PyPI。

**Linux 界面花屏或打不开**：
```bash
sudo apt install libxcb-xinerama0 libxcb-cursor0
export QT_QPA_PLATFORM=xcb
```

**界面太大或太小**：设置 → 高级 → 高分屏缩放，选一个合适的比例，保存后重启。共 跟随系统 / 80% / 90% / 100% / 125% / 150% / 175% / 200% / 300% 9 档；会把界面撑出当前屏幕的档位会自动隐藏（所以小屏上最高只能选到 150% 左右，大屏才看得到 200% / 300%）。

### 刮削问题

**刮不出数据**：
1. 检查设置里有没有勾选对应类型的网站
2. 点左侧导航「检测网络」页的「开始检测」，看网站可不可达
3. 配置代理（设置 → 网络）

> 小技巧：站点选择下拉框会记住你最近一次检测结果（✅绿圆点=可连通、⚠️黄=需关注、❌红=连不通，悬停可看检测时间与是否走代理），跑过一次检测后即可据此挑选网站；其中 **DMM/MGStage 需要日本节点**、**JavDB/JavDB_API 不能使用日本节点**（下拉框中有后缀标注）。

**有的网站一直失败**：可能是被墙了。试试：
- 改用免 CF 通道（JavDB_API、JavDB_APP、Missav_API、R18.dev、TheJavDB，默认已加入网站源）
- 或者配置CloudFlare 绕过服务（设置 → 网络 → CloudFlare 绕过服务，填 TRAWL / FlareSolverr 地址；本地 FlareSolverr 填 `http://127.0.0.1:8191` 开头，不要写成 `https`）
- JavLibrary 遇 Cloudflare JS challenge 时会自动 fallback 到 Selenium+Edge headless 获取页面（cf_selenium_bypass，默认开启，需要 Windows 10/11 + Edge 浏览器，无 Edge 环境优雅降级，连续失败 3 次进入 5 分钟冷却）

**刮出来的标题是日文/英文**：设置 → 翻译，开启翻译并选 Google 或 Bing。

### 演员数据库

**数据库在哪**：`userdata/actor_database.xlsx`

**软件工具页操作**：软件工具页「演员数据维护」区域有十一个操作——补全中文名（按 TMDB ID 补翻译）、补全 LibreDMM 链接、补全别名（可选来源：TMDB、minnano 或 JavDB；默认仅补缺别名的行，勾选「全量更新」则并入全部行且不覆盖本地已有别名；配套「起始行/限量」分片续跑——中断后日志输出"将起始行填入 N-1 即可续跑"，处理日志带 [行N] 前缀便于人工定位，长任务无需从头重发请求）、JavDB 中文名（从 JavDB 移动端 API 查询演员中文名/繁体名，仅处理「中文名 == 日文原名」的行，用 name_zht 转简体补全，无需 TMDB API KEY，支持分片续跑）、minnano 补全（从 Minnano-av 补缺生日/简介，日文字段自动翻译）、检查用户库（扫描格式/结构/数据异常并弹窗报告，安全项可一键自动修复，tmdb 项给人工修复步骤）、剔除男演员、校验 tmdbid 有效性、更新 nfo tmdbid、打开演员数据库、停止当前维护任务。前九个自动扫描数据库并批量处理，打开用系统默认程序打开 xlsx 供手工编辑，停止按钮独立于软件界面刮削停止、一键请求停止当前维护任务（会保存已处理部分，可再次运行继续）。每个联网维护工具默认限量 5000 条逐片处理，配合幂等可多次运行完成全部 2 万+ 行。进度实时显示在日志页。

**数据库坏了**：有备份就用备份恢复。可以定期备份这个文件。

**演员 TMDB ID 查不到**：
- 换几种名字搜（日文名、别名）
- 先去 TMDB 网站确认这个演员有没有收录
- 手动在 Excel 里填上 TMDB ID

**TMDB 请求太快报错（429）**：调低并发数（建议 3），开启限流（默认每秒 3.5 次），等一会儿再试。

**Emby 演员头像上传不成功**：
- 检查 Emby 地址和 API 密钥是否正确
- 确认网络能通 Emby 服务器
- 使用左侧导航「演员管理」查看具体错误信息

**Emby 4.9 剧照不显示**：v2.0.1 已修复，`behind the scenes` 目录下同时保留 .jpg 和 .mp4，兼容新旧版 Emby。

### 网络

**怎么拿 TMDB API KEY**：
1. 打开 https://www.themoviedb.org/
2. 注册账号
3. 在设置里申请 API Key
4. 填到 MDCx 设置里

**配置代理**：设置 → 网络 → 代理，支持 HTTP/HTTPS/SOCKS5。只对"走代理网站"域名列表中的站点走代理，其他默认直连；默认列表包含 `amazon.co.jp, m.media-amazon.com, xcity.jp, minnano-av.com, avbase.net, javbus.com, javdb.com, javlibrary.com, r18.dev, mgstage.com, prestige-av.com, seesaawiki.jp, avsox.click, avsox.com, avmoo.shop, avmoo.com, avheat.shop, avheat.com, heyzo.com, caribbeancom.com, 1pondo.tv, pacopacomama.com, 10musume.com, mywife.cc, github.com, raw.githubusercontent.com, google.com, missav.ws, missav.live, aventertainments.com, javfree.me, 7mmtv.sx, avsex.cc, getchu.com, dl.getchu.com`，可按需追加。

**Cloudfleare 校验服务**：设置 → 网络 →「Cloudfleare 校验服务」可填写可信落地域名（逗号分隔，支持 `*.example.com` 子域通配，如 `javbus.com,*.javbus.com`）。用于校验 Bypass 服务落地或重定向后的最终域名，防止第三方 Bypass 服务被劫持时把恶意页面当数据写入 NFO；留空表示不校验（默认）。

> 这个框**不是"哪些站点不走 Bypass"的名单**：Bypass 对全局自动生效（命中 Cloudflare 挑战页即触发），填不填都照常走。它只在**已经走了 Bypass 之后**校验落地页面的域名，名单外的站点若走 Bypass 且落地域名不命中，其响应会被直接拒收（日志出现 `🧱 mirror 落地域名不在白名单内，已拒绝: ...`）。
>
> 两个匹配细节：`*.example.com` **只匹配子域，不匹配裸域名本身**，所以要同时覆盖 `javdb.com` 和 `www.javdb.com` 需写 `javdb.com,*.javdb.com`；域名大小写不敏感，端口与协议不参与匹配。除非你在自建/审计 Bypass 服务，一般留空即可。

**刮削中途退出，重开要重新刮一遍吗**：不用。刮削进度自动保存到WAL模式SQLite本地数据库userdata/scrape_state.db中，程序重启或崩溃后再次刮削，会自动跳过已完成的文件、恢复上次失败的未超限文件，最多自动重试3次，从上次进度继续，读取模式不受断点续刮缓存干扰，始终处理全部选中文件，如需清除缓存重新全量刮削，可使用「软件工具」页的「刮削缓存管理」重置。

**NFO 在 Emby 里显示不出来**：
- 确认刮削时勾了「下载 NFO」
- 刷新 Emby 媒体库
- 检查 NFO 文件格式是否正确

## 实际场景

### 场景：新建媒体库

第一次用 MDCx 建立完整媒体库的操作路径：

1. 安装好程序，设置待刮削视频目录
2. 刮削设置里配好有码/无码网站源
3. 下载设置勾选海报、缩略图、NFO，开启人脸裁剪
4. 翻译选 Google，勾标题和简介
5. 选正常模式，扫描 → 勾选全部 → 点开始
6. 等刮完后，在 Emby 添加媒体库指向输出目录，刷新
7. 再到左侧导航「演员管理」里同步演员信息到 Emby

### 场景：日常补新片

每周下载新视频后的操作：

1. 把新视频扔到媒体文件夹
2. 开 MDCx，点「开始」——断点续刮会自动跳过已刮削且未变化的文件，只刮新增和失败的
3. 检查失败列表，右键「重新刮削」或「输入网址重新刮削」单独处理

### 场景：补充缺失的封面/缩略图

刮削完成后发现某个影片缺少封面图或缩略图：

1. 进入左侧导航「软件工具」页面，找到「补全封面图片」区域
2. 输入番号（多个番号用空格分隔，如 `SSIS-001 ABF-371`）
3. 勾选「覆盖已有图片」可重新下载已存在的封面
4. 取消「添加水印」可跳过水印步骤
5. 点击「开始补图」，进度和结果输出到日志页

工具会自动复用当前配置的站点优先级、命名、裁切和水印规则，无需额外配置。

### 场景：找风格相似的影片

刮削完成后想找同风格的其它片（同系列/同片商/同标签）：

1. 在右侧结果树中右键点击任意影片
2. 选择「查看相似片推荐」
3. 弹出对话框按相似度排序展示推荐影片（基于标签IDF加权Jaccard相似度+系列/片商/发行商/导演/评分/年份/时长/演员等多维特征本地离线计算）
4. 双击推荐项可跳转到对应影片（历史结果不在当次结果树中时仅提示番号）

推荐基于全部历史刮削结果（含跨会话），刮削的影片越多推荐越准，全程本地计算无需联网。

所有爬虫站点都拿不到图时，会自动走 **官方图源直链兜底**：① **DMM**：按番号直构 DMM 官方 CDN 高清封面，内置约 110 个主流系列前缀表并自动学习未收录厂牌的前缀（学习数据保存在 `userdata/dmm_prefix_learned.json`）；优先下载 DMM 高清竖版图作海报，竖版不存在时下横版高清图并自动裁剪成海报；无码番号（FC2/HEYZO 等）不会命中 DMM 兜底。② **MGStage**：DMM 不收录的素人番号（LUXU/OTIM 等）直构 MGStage 官方 CDN——横版大图作封面、竖版图作海报。默认开启，可在设置 → 下载「下载高清图」组关闭。

### 场景：管理 Emby 演员头像和简介

Emby 中的演员缺少头像或简介时，可以使用内置的演员管理工具：

1. 点击左侧导航「演员管理」打开管理器
2. 在弹窗中填写 Emby 地址和 API 密钥，点击「连接 Emby」
3. 点击「获取演员列表」，选择要管理的媒体库
4. 从下拉框选择获取模式（如「缺失头像或缺失简介」；另有仅缺失简介 / 仅缺失头像 / 头像和简介都缺 / 重新获取所有演员详情 / 重新获取简介、头像或两者）
5. 点击「根据设定获取数据」（再次点击可取消），按可配置的数据源优先级从 Gfriends / Graphis.ne.jp / Minnano-av / 本地文件夹匹配头像和背景图，从本地演员库 / 维基百科 / Minnano-av / 数据库匹配简介和出生日期
6. 表格中绿色行表示有更新项，点击「开始全部更新同步」写入 Emby（同步完成后自动刷新演员列表）
7. 「设置」可配置数据源优先级、演员类型过滤/去重、本地头像目录等；「数据源测试」可输入演员名逐源验证结果
8. 演员行的左键手势分三段：单击只选中（保持该格原有底色，不再铺浅蓝底，只在四周显示一圈蓝条表示「选中」），再次单击进行内编辑（姓名/出生日期/出生地/详情/标签格，回车或点别处提交；编辑中的格子为纯白底 + 四周一圈蓝边表示「编辑中」，不再铺整块蓝底），快速双击或连续快速点击打开详情编辑对话框（**编辑状态中双击/连续点击同样会弹出详情窗**；只读列如状态/头像/简介/影片数快速双击即打开）：可编辑简介/信息、单独同步头像/简介；在姓名/出生日期/出生地/详情/标签格上按鼠标右键会弹出小菜单（复制内容 / 编辑内容 / 查看详情），分别等于「复制该格的完整内容」「再次单击进行内编辑」「双击打开详情窗」（只读列与空白处右键不弹菜单）；左右两栏顶部的头像预览框各占本栏三分之一高度并随窗口自动伸缩，头像在框内居中显示；中栏「信息」表始终完整显示全部五行（标签/年份/生日/出生地/外部 ID，无需拖滚动条），所需高度由上方「简介」让出；窗口内「本地头像目录」输入框与【浏览】按钮就在五个功能按钮**正上方**，改完路径自动保存；最大化时六个按钮会等比变高、宽度不变，其中【浏览】的宽度会跟着窗口状态走 —— 平时与【只同步简介】一样宽，最大化时收成它的一半；窗口每次打开都严格居中显示在屏幕中央，关闭前你手动挪动的位置会在下次打开时保留
9. 「清空缓存文件夹」可清理已下载的头像缓存

注意：API 密钥在 Emby 管理后台 → 高级 → API 密钥中生成。
